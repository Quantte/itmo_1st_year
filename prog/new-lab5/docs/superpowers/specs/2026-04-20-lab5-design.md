## 2. Key Abstractions

### ExecutionContext
A single object passed into every command's `execute()` method. Contains:
- `CollectionManager` — owns the LinkedList and all mutation/query operations
- `Storage` — load/save interface
- `ConsoleReader` — abstracted input (stdin or script file)
- `ConsoleWriter` — single output point

This is the seam for the future server-client split: swap `ConsoleReader`/`ConsoleWriter` for network streams and the commands are unchanged.

### Storage interface
```java
public interface Storage {
    LinkedList<Product> load();
    void save(LinkedList<Product> collection);
}
```
`JsonFileStorage` implements it using `InputStreamReader(FileInputStream)` for reading and `OutputStreamWriter(FileOutputStream)` for writing, as required. Gson is configured with `setDateFormat("yyyy-MM-dd'T'HH:mm:ss")` and `setPrettyPrinting()`.

### Command interface
```java
public interface Command {
    String getName();
    String getDescription();
    void execute(String[] args, ExecutionContext ctx) throws ExitException;
}
```

### CommandRegistry
Maps command name → `Command` instance. Maintains a fixed-size deque of the last 9 executed command names (no args) for the `history` command.

## 3. REPL Loop

```
Main
 └─ reads LAB5_DATA env var → error + exit if missing
 └─ JsonFileStorage.load() → warn + empty collection if file unreadable
 └─ builds ExecutionContext
 └─ registers all 16 commands in CommandRegistry
 └─ App.run()

App.run():
  loop:
    print "> "
    read line
    parse: first token = command name, rest = args
    CommandRegistry.execute(name, args, ctx)
      → record name in history deque
      → dispatch to Command.execute()
    print result
  until ExitException is thrown
```

**execute_script:** feeds lines from a file into a fresh `ConsoleReader`. The context tracks a `Set<String>` of currently-executing absolute script paths; if a script tries to execute itself (directly or transitively), it prints an error and skips.

## 4. Data Flow & ID Generation

`CollectionManager` owns a `LinkedList<Product>` and a `nextId` counter.

On `load()`: scans all loaded products, sets `nextId = max(ids) + 1`. IDs are never reused after removal.

On `add`: assigns `nextId` to the new product, increments `nextId`.

`compareTo` on `Product`: sorts by name ascending, then by price ascending (natural order used by `add_if_max` and `print_descending`).

## 5. Interactive Input & Validation

`ProductBuilder` constructs a `Product` interactively field-by-field using `ConsoleReader`.

Rules:
- On invalid input: print specific error message, re-prompt the same field.
- Nullable fields: empty line → `null`.
- Enums: print all constants first, read by name (case-insensitive), empty line → `null` if nullable.
- If user enters empty line at "Enter owner name:" → entire `Person` is `null` (owner is nullable).

| Field | Constraint |
|---|---|
| `name` | non-null, non-empty string |
| `coordinates.x` | float, ≤ 597, non-null |
| `coordinates.y` | long, non-null |
| `price` | float, > 0, non-null |
| `partNumber` | nullable string |
| `unitOfMeasure` | nullable enum |
| `owner.name` | non-null, non-empty (only asked if owner not skipped) |
| `owner.weight` | double, > 0 |
| `location` | nullable — empty line at "Enter location? (y/n):" skips |
| `location.x` | double |
| `location.y` | int, non-null |
| `location.z` | int |

## 6. Error Handling Policy

| Situation | Behavior |
|---|---|
| `LAB5_DATA` env var not set | Print error, exit |
| File not found / unreadable | Warn, start with empty collection |
| File not writable on `save` | Print error, do not crash |
| Unknown command | Print "Unknown command. Type 'help'." |
| Wrong arg type (e.g. string for id) | Print specific error message |
| `update` with non-existent id | Print "No element with id X." |
| `remove_by_id` with non-existent id | Print "No element with id X." |
| `remove_any_by_price` with no match | Print "No element with that price." |
| `add_if_max` with empty collection | Add unconditionally |
| `remove_first` on empty collection | Print "Collection is empty." |
| Script file not found | Print error, skip script execution |
| Script cycle detected | Print error, skip the recursive call |
| Any unhandled exception at REPL boundary | Print error, continue loop |

## 7. Future Migration Notes

**Server-client split (lab6):** The `ExecutionContext` seam means: server owns `CollectionManager` + `Storage` + command execution; client owns `ConsoleReader` + `ConsoleWriter`. Commands stay unchanged. Add a `Request`/`Response` envelope and a TCP dispatcher around `CommandRegistry`.

**PostgreSQL migration:** Implement `PostgresStorage implements Storage`. No other code changes required.
