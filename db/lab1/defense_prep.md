## 1. Архитектура ANSI-SPARC

### Что это?
Стандарт 1975 года, описывающий трёхуровневую архитектуру СУБД. Цель — отделить пользовательские представления от физического хранения данных.

### Три уровня:

| Уровень | Название | Что описывает | Кто работает |
|---------|----------|---------------|--------------|
| Внешний | External / View level | Пользовательские представления (подмножество данных) | Конечные пользователи, приложения |
| Концептуальный | Conceptual level | Логическая структура всей БД (таблицы, связи, ограничения) | DBA (администратор) |
| Внутренний | Internal / Physical level | Физическое хранение: файлы, индексы, страницы | СУБД, ОС |

### Два уровня отображения (маппинги):
- **Внешний ↔ Концептуальный** — как представление отображается на концептуальную схему
- **Концептуальный ↔ Внутренний** — как логическая схема отображается на физические структуры

### Логическая независимость данных
Изменение концептуальной схемы (добавление столбца) не требует менять внешние представления.

### Физическая независимость данных
Изменение физического хранения (смена индекса, файловой системы) не требует менять концептуальную схему.

### Пример из нашей лабы:
- **Внешний уровень:** `CREATE VIEW encounters_today AS SELECT ... FROM encounter WHERE ...`
- **Концептуальный:** наши таблицы `encounter`, `dinosaur`, `person`, etc.
- **Внутренний:** как PostgreSQL хранит строки на диске (heap файлы, WAL, индексы)

## 2. Модель «Сущность-Связь»

### Сущность (Entity)
Объект реального мира, о котором хранится информация.

**Классификация сущностей:**

| Тип | Описание | Пример из лабы |
|-----|----------|----------------|
| **Стержневая** (kernel) | Независимая, первичный ключ не содержит FK | `dinosaur_species`, `dinosaur`, `person`, `location` |
| **Ассоциация** (associative) | Связывает две+ сущности M:N, PK может включать FK | `encounter` |
| **Характеристика** (characteristic) | Уточняет другую сущность, существование зависит от родителя | `encounter_action` |

### Атрибуты
- **Простой** — неделимый (name, age)
- **Составной** — делится на части (ФИО = имя + фамилия)
- **Однозначный** — одно значение
- **Многозначный** — несколько значений (телефоны)
- **Производный** — вычисляется (возраст из даты рождения)

**Ключ** — атрибут (или набор), однозначно идентифицирующий экземпляр сущности.
- **Потенциальный ключ** — минимальный уникальный набор атрибутов
- **Первичный ключ (PK)** — выбранный потенциальный ключ
- **Суррогатный ключ** — искусственный (SERIAL id)
- **Естественный ключ** — из предметной области (latin_name)

### Виды связей

| Мощность | Обозначение | Пример |
|----------|-------------|--------|
| Один к одному | 1:1 | Паспорт ↔ Человек |
| Один ко многим | 1:N | Вид → Особь |
| Многие ко многим | M:N | Динозавр ↔ Человек (через encounter) |

**Обязательность участия:**
- **Обязательная** — каждый экземпляр должен участвовать в связи (динозавр обязан быть вида)
- **Необязательная** — может не участвовать (человек может не иметь столкновений)

### Ограничения целостности

| Тип | Что проверяет | Реализация в PostgreSQL |
|-----|---------------|-------------------------|
| **Целостность сущности** | PK NOT NULL и уникален | `PRIMARY KEY` |
| **Ссылочная целостность** | FK указывает на существующий PK | `FOREIGN KEY ... REFERENCES` |
| **Доменная целостность** | Значения в допустимом диапазоне | `CHECK`, `NOT NULL`, `ENUM`, типы |
| **Пользовательская** | Бизнес-правила | Триггеры, процедуры |

**Действия при нарушении ссылочной целостности:**
- `ON DELETE RESTRICT` — запретить удаление родителя
- `ON DELETE CASCADE` — удалить дочерние записи
- `ON DELETE SET NULL` — обнулить FK
- `ON DELETE SET DEFAULT` — поставить значение по умолчанию

## 3. DDL (Data Definition Language)

DDL — подмножество SQL для определения структуры объектов БД.

### Основные операторы:

```sql
-- Создание таблицы
CREATE TABLE table_name (
    col1 type1 constraints,
    col2 type2 constraints,
    table_constraint
);

-- Изменение таблицы
ALTER TABLE table_name ADD COLUMN col type;
ALTER TABLE table_name DROP COLUMN col;
ALTER TABLE table_name ALTER COLUMN col TYPE new_type;
ALTER TABLE table_name ADD CONSTRAINT name CHECK (...);

-- Удаление
DROP TABLE table_name;               -- ошибка если есть зависимости
DROP TABLE table_name CASCADE;       -- удалить зависимые объекты тоже
DROP TABLE IF EXISTS table_name;     -- без ошибки если не существует

-- Схемы
CREATE SCHEMA schema_name;
SET search_path TO schema_name;
```

### Ограничения (constraints) в PostgreSQL:

```sql
col INTEGER PRIMARY KEY                       -- первичный ключ
col INTEGER NOT NULL                          -- обязательность
col INTEGER UNIQUE                            -- уникальность
col INTEGER CHECK (col > 0)                   -- проверочное условие
col INTEGER REFERENCES other_table(id)        -- внешний ключ
col INTEGER DEFAULT 42                        -- значение по умолчанию
```

### Типы данных PostgreSQL (использованные в лабе):

| Тип | Описание |
|-----|----------|
| `SERIAL` | Автоинкремент (4 байта, 1..2^31) |
| `BIGSERIAL` | Автоинкремент (8 байт) |
| `INTEGER` / `INT` | Целое (4 байта) |
| `SMALLINT` | Маленькое целое (2 байта) |
| `NUMERIC(p,s)` | Точное вещественное (precision, scale) |
| `VARCHAR(n)` | Строка до n символов |
| `TEXT` | Строка неограниченной длины |
| `TIMESTAMP WITH TIME ZONE` | Дата+время с часовым поясом |
| `ENUM` | Перечисление фиксированных значений |

## 4. DML (Data Manipulation Language)

DML — подмножество SQL для работы с данными.

### Основные операторы:

```sql
-- Вставка
INSERT INTO table (col1, col2) VALUES (val1, val2);
INSERT INTO table (col1, col2) VALUES (v1, v2), (v3, v4);   -- несколько строк

-- Обновление
UPDATE table SET col1 = val1 WHERE condition;

-- Удаление
DELETE FROM table WHERE condition;
DELETE FROM table;   -- удалить все строки (осторожно!)

-- Выборка
SELECT col1, col2 FROM table WHERE condition ORDER BY col1;
SELECT * FROM table;

-- Соединения (JOIN)
SELECT d.nickname, s.name
FROM dinosaur d
JOIN dinosaur_species s ON d.species_id = s.id;

-- Агрегация
SELECT species_id, COUNT(*) FROM dinosaur GROUP BY species_id;
```

### Пример из нашей лабы:

```sql
-- Получить все столкновения с именем динозавра и человека
SELECT
    s.name          AS species,
    d.age_category,
    p.first_name    AS person,
    l.name          AS location,
    e.outcome,
    e.encounter_ts
FROM encounter e
JOIN dinosaur d        ON e.dinosaur_id = d.id
JOIN dinosaur_species s ON d.species_id = s.id
JOIN person p          ON e.person_id = p.id
JOIN location l        ON e.location_id = l.id
ORDER BY e.encounter_ts;
```

## Частые вопросы преподавателей

**Q: Почему id — суррогатный, а не natural key?**
A: Естественные ключи могут меняться (имя, Latin name может быть скорректировано), суррогатный стабилен и гарантированно уникален.

**Q: Почему encounter — ассоциация, а не стержневая?**
A: Потому что её существование зависит от существования минимум трёх других сущностей. Она реализует связь M:N между динозавром и человеком.

**Q: Чем NUMERIC лучше FLOAT для веса/высоты?**
A: FLOAT — приближённый (floating point), NUMERIC — точный. Для физических параметров важна точность до заданного числа знаков без потерь на округление.

**Q: Почему ON DELETE CASCADE у encounter_action, а RESTRICT у encounter?**
A: Действия — неотъемлемая часть столкновения, при удалении столкновения теряют смысл → CASCADE. Столкновение — ценная запись, удалять его при удалении динозавра/человека опасно → RESTRICT.

**Q: Что такое ссылочная целостность?**
A: Гарантия, что FK всегда указывает на существующую строку в родительской таблице (или NULL, если допускается).
